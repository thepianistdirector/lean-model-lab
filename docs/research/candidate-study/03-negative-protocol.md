# A separately registered negative investigation

This contract starts new work after both positive-advance feasibility branches stopped. Their failures remain unchanged: the 14B full/slice cell is 1/8 versus 2/8 per pair, and the 0.5B original/explicit-instruction cell is 1/8 versus 0/8. Those failures do not authorize more prompt or seed search. Root separately approved the following finite negative investigation before any of its native requests.

The question is whether exact semantic closure, actual model correctness and a trained acceptance rule diverge on a prospectively fixed population of fresh record graphs. Baseline quality failure alone is insufficient evidence: a selector might recover correctness by choosing the other representation. Therefore the experiment directly measures the ceiling attainable by selecting between the two observed outputs, harmful and beneficial changes, and the effect of selecting semantically relevant records instead of simply shortening a prompt. It also trains and deploys the actual fixed-complexity controller, even if calibration returns an always-full refusal.

All studies use the original RECORD-LANGUAGE v1, Qwen2.5-0.5B-Instruct FP16 profile v2, context 24 records, concurrency one, two compute threads, no cross-request prefix reuse, a 32-token output cap and two AB/BA pairs. The fixed mixed generator cycles lookup, reference-chain and last-write/update cases. At 32 requests it offers 11/11/10 cases; at 128 it offers 43/43/42. These are subgroup denominators, not 128 examples of each family.

The new phase offers exactly 1,920 native requests. Including the 64 completed feasibility requests, the investigation totals 1,984, below its 2,000-request ceiling. The repeated use of tables is explicit; native completions are not independent table samples.

For request *i* in repetition *r*, let *F(i,r)* and *S(i,r)* indicate exact correctness of the observed full and sliced outputs. The per-repeat oracle is `F(i,r) OR S(i,r)`. Its accuracy divides by every offered request, including both-wrong, missing and failed requests. It never uses the full response from one repetition and the sliced response from another. A second conservative oracle is `(full correct in every repetition) OR (slice correct in every repetition)`, corresponding to selecting one observed arm per request that succeeds in all repetitions.

If a defined oracle ceiling is below 95%, no selector restricted to those observed outputs can reach 95% on that population and repetition definition. This does not rule out a different prompt, checkpoint, generated output, sampling procedure or learning method. An oracle ceiling at or above 95% would preserve routing sufficiency in principle; it would not establish an executable policy or measured oracle speed.

Every comparison retains both-correct, full-only-correct, candidate-only-correct and both-wrong cases. One fresh full-only-correct response under an independently checked semantic slice extends the original model-answer counterexample. Zero observed harm would not prove general equivalence. Family, closure size (1, 2, 3+), overwritten writes (0, 1+) and first/last retained position (0–333, 334–666, 667–1000 permille) are fixed marginal descriptive strata. No outcome-selected bins, significance tests or independent-repeat assumptions are used.

The shortening control uses the exact fit tables and the same number of retained records as the dependency slicer. It has separate actual full/control executions with equal request counts and balanced repetitions. Actual token differences remain visible. This tests whether selecting the correct dependencies affects model answers beyond merely reducing record count. Its deliberate semantic failures are reported, not mistaken for a broken dependency certificate. It is development evidence and does not enter protected confirmation.

The actual trained artifact is a depth-two binary harmful-omission tree fitted by the product from raw-audited native labels. Its five features are total records, dependency-closure records, all overwritten writes, and minimum/maximum retained record position in permille. It receives no answer, key/value text, request ID, seed or family-name predictor. Conservative labels require correctness in all repetitions for each arm. The finite calibration grid is 0, .05, .1, .25, .5 and 1. A candidate operating point needs at least eight accepted cases, zero observed calibration harm, at least 95% routed calibration accuracy and positive dispatch-to-completion request savings. If none qualifies, the artifact explicitly chooses ALWAYS_FULL.

A refusal is the result of this predeclared learner and calibration rule. It neither demonstrates that all learning is impossible nor becomes a successful compression result. If the trained gate matches the simple or unconditional policy, learning has not established added value. An independent source-body grouping check excludes accidental fit/calibration table overlap. Shared Unix identity provides workflow separation, not isolation against a malicious writer.

The contract fixes confirmation seeds, generator and counts before population generation. After actual controller freeze, constructing the exact confirmation recipes necessarily generates and hashes that declared population. The first such access is recorded; all three exact recipes are frozen before any native confirmation outcome is accessed. Nothing is retuned on confirmation.

The existing quality and efficiency gates stay intact: both arms must reach 95%, aggregate candidate accuracy cannot regress in any pair, and the prescribed full-wall and tail limits still apply. Timing for ineligible arms is descriptive. Calibration request durations omit preparation and training costs and cannot establish full-cost improvement. Model acquisition, build, source preparation, native labeling, controller training, tokenization, candidate analysis, failures, waiting and the original allocation span remain separately accounted without adding overlapping scopes.

The entire investigation has at most 10,800 seconds of native product execution, including the prior 523.026 seconds. After the first fit study, remaining requests are projected at 1.5 times its enclosing execution seconds per request. If this exceeds either remaining native time or the original shared allocation deadline, the phase stops before more native execution; it does not select a different matrix from outcomes. All heavy runs use the shared queue helper and the immutable archive04.
