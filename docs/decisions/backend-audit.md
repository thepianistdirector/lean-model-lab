## Single policy, slots and observability

The sole difference is request field `cache_prompt=false` in A and `cache_prompt=true` in B. This is same-slot common-prefix KV reuse, not a batching experiment. Source inspection confirms that explicit slot selection can still enter the separate global prompt-cache logic, so explicit slot IDs alone are insufficient. Disable the global RAM prompt cache and idle-slot cache in both arms with `--cache-ram 0 --no-cache-idle-slots`, disable shifting reuse with `--cache-reuse 0`, and use `--no-kv-unified`. This retains the per-slot KV prefix that `cache_prompt` controls. [Slot selection and prefix-reuse implementation](https://github.com/ggml-org/llama.cpp/blob/bb4caa7540188872173c44d161602d9271386413/tools/server/server-context.cpp).

Launch the same server flags for each arm: `--parallel C --ctx-size (2048*C) --threads 2 --threads-batch 2 --threads-http 4 --device none --gpu-layers 0 --no-context-shift --no-ui --no-agent --cache-ram 0 --no-cache-idle-slots --no-kv-unified --cache-reuse 0`, where C is 1 or 4 and the context expression is computed by the coordinator. Bind a project-specific loopback port or supported Unix socket. Keep continuous batching enabled and identical. Use explicit `id_slot = request_index % C` and process each lane serially. Validate `/slots` reflects C slots, sufficient context and the expected slot for every response. A fresh server per arm prevents previous-arm reuse. Built-in warmup must be identically configured and its full time retained.

The pinned native `/completion` request accepts `prompt`, `id_slot`, `cache_prompt`, `stream=true`, `return_tokens=true`, `n_predict=32`, `temperature=0`, `seed=20260907`, `ignore_eos=false`, `stop=[]`, `timings_per_token=true`, and `return_progress=true`. Freeze all sampler parameters/defaults read back from `generation_settings`. Use the native endpoint rather than an OpenAI compatibility response when retaining token IDs. Partial records have `stop=false`, `content`, `tokens`, `id_slot`, `tokens_predicted` and `tokens_evaluated`; progress-only records can add `prompt_progress={total,cache,processed,time_ms}`. Final records have `stop=true`, the same accounting fields, `generation_settings`, `truncated`, `stop_type`, `stopping_word`, `tokens_cached` and `timings`. Retain raw records before normalization. [Exact result serialization](https://github.com/ggml-org/llama.cpp/blob/bb4caa7540188872173c44d161602d9271386413/tools/server/server-task.cpp).

The pinned source sets final `content=""` and `tokens=[]` in streaming mode: collect emitted output from partial records and verify this in the runtime probe. Final `tokens_evaluated` is the full input-token count. Despite ambiguous README wording, final `tokens_cached` is assigned the final slot's prompt-token occupancy, not the reused-prefix count; use `prompt_progress.cache` and `timings.cache_n` for observed reused-prefix accounting and retain final occupancy separately. `timings.prompt_n` counts newly processed prompt tokens; `timings.predicted_n` counts generated tokens. The duration keys are `prompt_ms`, `predicted_ms`, plus their `*_per_token_ms` and `*_per_second` derivatives. [Timing serialization](https://github.com/ggml-org/llama.cpp/blob/bb4caa7540188872173c44d161602d9271386413/tools/server/server-common.cpp). EOS tokens may be counted in `tokens_predicted` while not emitted as ordinary content; preserve generated-token accounting separately from visible token IDs and validate the observed relation. A multi-token SSE event has one receipt timestamp. Do not invent per-token gaps or engine execution-start/queue timestamps. Client TTFT and end-to-end timing are measurable; engine absolute start and internal queue are UNAVAILABLE with this ordinary API. Server durations are separate observations, not synchronized coordinator timestamps.

The native API documents numerical differences when caching changes batch processing; greedy decoding does not promise parity. Both arms must independently pass the absolute quality gate and the additional exact-token parity check. If parity fails, retain it as an ineligible comparison rather than changing thresholds. `n_predict` may exceed the requested cap for a partial multibyte token, so retain any overshoot and reject it under the frozen maximum. [Pinned native API contract](https://github.com/ggml-org/llama.cpp/blob/bb4caa7540188872173c44d161602d9271386413/tools/server/README.md).

## Frozen quality and finite allocation proposed for approval

Use [the first workload contract](../benchmarks/first-workload.md): 128 fixed public synthetic key-copy requests, 32 in each of four filler-word strata, seed 20260907, identical all-zero arrivals, concurrency 1/4, at most 32 requested output tokens, native EOS allowed. This is a finite queued workload. At least 95% exact expected key answers after outer whitespace stripping must pass separately in each arm/run; expected keys precede model observation. Exact paired output token IDs are an additional eligibility constraint. These conditions test this narrow task, not general language competence.

Three paired rounds per concurrency in predeclared AB/BA/AB order give 12 measured arm runs and at most 49,152 requested output tokens before warmup/recovery overhead. AB/BA/AB is only partially balanced; report its unequal start count and do not claim a fully balanced design. Pair-level ratios/ranges, unstable p95/p99, 5% practical-throughput threshold and 10% tail-regression guardrail remain frozen. No selected fast runs, changed quality thresholds or free failed attempts.

Approval requested is **one project-scoped acquisition/build and this complete campaign**, capped at **2 hours total full wall including acquisition/build/warmup/evaluation/recovery**, **5 GiB additional project disk**, **4 GiB peak aggregate project RAM**, **2 engine compute threads**, at most **one heavy project job**, and **zero paid/GPU/cloud compute**. HTTP/coordinator threads are bounded separately and are not additional inference thread pools. Stop and retain failure accounting at any cap or unsafe shared-host pressure; ask for a new allocation rather than expanding automatically. Enforce wall/process/address-space limits where available and record that RSS/disk polling can overshoot between observations; do not claim hard cgroup isolation without proving it. C=4 means four decoder slots inside the same two-thread engine.

Initial feasibility is an inference from the 1.27GB artifact and observed free capacity, not a runtime result. The full campaign may exceed its cap or miss quality; that remains a valid retained failure and an incomplete release gate. External reproduction consumes a separately identified authorized environment/allocation; this local allocation is not unlimited replication authority.

## Network, security, rollback and remaining gates

Acquisition contacts public GitHub and Hugging Face artifact/CDN hosts over HTTPS, with no private prompts or account credentials. Review redirects and final URLs, verify the pinned model digest, and keep downloads/build/cache/logs exclusively inside this project. Inference uses local reviewed artifacts and loopback IPC only; no upstream inference calls or automatic model downloads. Disabled TLS/tools/UI options reduce unused dependencies and network features; they are not a security sandbox. The adapter should launch with an allowlisted environment, reject remote model URLs, and accept only its own loopback server. Weights are inert GGUF data but native parsers still require trusted provenance and bounded resources. This review does not attest that the backend has no vulnerabilities or certify arbitrary public-server exposure.

The reviewed stable source is maintained upstream and supplies the needed cache/stream API. Preserve its notices plus all linked vendored notices in any distributed binary; source-recipe-only distribution still needs accurate dependency attribution. No public backend/weight redistribution is authorized by this decision. Rollback stops only project-owned process groups and removes only verified newly created project artifact/build paths after recording evidence; it leaves repository work, sibling projects and system configuration intact. Replacing the adapter/model starts a new reviewed comparison identity.

Remaining gates: owner acceptance of this exact graph/model/allocation; actual source/model retrieval and integrity checks; C++17 build on this GCC host; runtime slot/tokenizer/cache/timing probes; real quality and paired measurements; resource-bound proof; external reproduction; any required human review and separate concrete publication decisions. No unsupported backend switch is an automatic fallback. SmolLM2-135M was considered, but an official small FP16 GGUF was not verified in this bounded audit; conversion would add a different dependency graph.
